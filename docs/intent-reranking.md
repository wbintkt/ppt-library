# 完整意图重排

原排序通过向量分和标题关键词加分决定结果。对“公安打击无人机黑飞”这样的查询，“公安使用无人机巡查”容易因词语重合排到前面，实际却把监管对象当成了执法工具。

现在在召回之后、返回 Top K 之前增加一次 qwen-flash 联合评审。请求保留用户完整原句（包括否定条件），模型先拆解主体、动作、作用对象和目的，再逐页根据标题和正文判断相关性。旧关键词分只参与候选选择，不叠加到重排结果上。

## 候选与评分

- 默认重排最多 60 页。候选多于上限时，从向量序和关键词序交替选取，防止标题加分挤掉业务关系正确的页面。召回未包含的页面仍无法被重排找回。
- 每页送入最多 300 字标题和 1800 字正文；正文超限时保留前 2/3、后 1/3，并标明中段省略。仅图片中的信息、被截断的正文不在此次评审范围内。
- 不发送来源、文件名、标签或旧分数，避免把文件主题和排名暗示当成本页业务证据。
- 模型返回每页的关系判断、相关性分和本页原文引用。服务端检查 ID 完整性、分数范围和引用是否在送入的正文/标题中；错配、弱关联、支撑材料分别有 0.25、0.39、0.79 的上限。
- “黑飞发现、告警、溯源”可以是公安治理的支撑内容，但不能被虚构成“公安实际执法案例”或“反制击落能力”。封面按查询意图判断，不做固定过滤。
- 成功时 `score` 与 `display_score` 都使用新的 0~1 相关性分，避免列表顺序和百分比冲突。这仍是模型评分，不是经人工标注校准的准确率，也不强制第一名为 100%。

API 增加向后兼容字段：

| 字段 | 含义 |
| --- | --- |
| `rerank_status` | `applied` 成功；`failed` 异常回退；`unavailable` 无 Key；`disabled` 已关闭；`skipped` 无候选 |
| `items[].rerank_reason` | 模型给出的简短关系判断，回退时为 null |
| `items[].rerank_evidence` | 模型引用的本页原文，回退时为 null |

现有前端可以直接消费结果，不需要改版。原因和证据暂供 API 排查使用。引用存在性检查不能证明模型解释一定正确，仍需真实业务评测。

## 故障与开销

每次搜索按候选量分 15 页/批串行调用模型，输入量随候选正文增长，会增加延迟和百炼用量。传给 SDK 的网络超时默认 30 秒（服务器已调 60 秒），不代表整次搜索的总耗时上限（SDK 在连接中断时可能自行补发）。

实测 qwen-flash 单批候选越多输出越不稳定（49 页单批成功率约 40%，15 页/批约 92%）：模型会提前收尾漏页，或引用因 PDF 提取换行/图标字符/多栏错乱而无法逐字对齐的正文。因此：

- 候选分 15 页/批顺序调用；单批内部漏页时对缺失页补调一次。
- 单批失败自动重试至多 3 次（模型输出有随机波动，重试显著提升成功率；首轮整批成功率实测约 97%）。
- 引用校验按“原文出现或字符覆盖率 ≥ 75%”判定，容忍提取文本的换行/图标字符/词序错乱，但完全虚构的引用（原文无对应字符）仍会使整批回退。
- 模型报错、响应截断、漏页（补调/重试后仍缺）、重复 ID、非法分数、虚构引用等情况最终整批恢复原有排序与显示分，不混合两套分数。

旧排除词降权只在回退路径执行，成功重排由完整原句判断否定关系。

向量调用失败但仍有 Key 时，关键词召回也可接受重排；未配置 Key 时继续使用原关键词搜索。扩大的关键词候选集仍须满足分类和文件过滤，本次同时修正了旧实现将这些过滤条件与关键词用 OR 连接的问题。

## 配置与部署

在 `backend/.env` 中可设置：

```dotenv
RERANK_ENABLED=true
RERANK_MODEL=qwen-flash
RERANK_CANDIDATE_LIMIT=60
RERANK_TEXT_CHARS=1800
RERANK_TIMEOUT_SECONDS=30
```

候选上限可设 50~100（搜索最多返回 50 页），正文上限 500~4000，超时 1~60 秒。模型需要支持 JSON 输出和非思考模式；不要直接切到仅支持思考模式的模型。服务复用数据库或环境中的 `DASHSCOPE_API_KEY`，不会把 Key 返回给前端。JSON 输出参数参考 [百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

审核合并后，在服务器更新代码、安装 `backend/requirements.txt` 并重启 `ppt-backend` 即可；无需重索引、迁移数据库、重建前端或重启解析 worker。Docker 部署需重建 backend，并通过 backend 的 environment 传入上述可选覆盖值。配置变更需要重启后端。

回滚可设置 `RERANK_ENABLED=false` 后重启后端，保留原召回排序方式。

## 验证

离线测试仅用替身模型，验证完整查询传递、截取 Top K 的时机、业务错配分数上限、证据校验和故障回退，不声称测出了模型准确率：

```bash
cd backend
venv/bin/python -m pip install -r requirements.txt pytest httpx
venv/bin/python -m pytest tests/test_intent_reranker.py tests/test_intent_reranker_transport.py tests/test_display_score.py -q
```

真实模型评测默认跳过；在已配置百炼 Key 的环境显式运行：

```bash
cd backend
RUN_LIVE_RERANK=1 venv/bin/python -m pytest tests/test_intent_reranker_live.py -v
```

它只发送手写合成素材，覆盖无人机工具/监管对象互换、封面检索、实际案例、银企服务方向、AI 作为工具或故障对象以及素材内指令干扰，会产生模型调用费用，不读取或修改素材库。

上线验收前刷新页面，清空前端内存中的旧搜索结果。使用真实库查询“找一个公安打击无人机黑飞的片子”，检查 `rerank_status=applied`，并确认违规飞行告警、黑飞感知/溯源页领先普通公安无人机巡查页和仅有标题的飞控封面。再反向搜索“公安用无人机巡查识别人车”，确认排序能随意图反转。用 60 页候选的真实请求观察延迟、回退率和引用质量，再决定是否调整模型、正文预算或超时。只通过离线测试不能替代这一步。
